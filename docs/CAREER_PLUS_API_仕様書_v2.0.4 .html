CAREER PLUS API

概要 ¶

はじめに ¶

CAREER PLUSのAPI機能は、求職者、企業、求人、進捗などの情報の追加、更新、削除、取得操作をHTTPを利用して提供するものです。 これにより、エントリーページや求人掲載ページ、マイページの作成や他システムとの連携をお客様自身で開発出来るようになります。

利用方法 ¶

  • ブラウザから直接APIを実行しないようお願い致します。
    ブラウザから直接APIを実行する場合、APIキーをブラウザに保持する実装となります。
    その場合、APIキーが漏洩し、第三者が本来の目的外でAPIを実行することが可能となります。

    例）Ajaxを利用したブラウザ内での非同期通信等一度サーバーへリクエストし、サーバーからAPIを実行して頂くようお願い致します。

  • 機械的に大量のリクエストを実行しないようお願い致します。

    例）パフォーマンステスト等

    1分間あたり240リクエストを超える場合、APIサービスを停止させて頂く可能性がございます。 何卒ご了承くださいませ。

準備 ¶

APIのFQDN ¶

APIのFQDNは下記となります。

https://api.careerplus.jp

使用例

https://api.careerplus.jp/v1/auth/token

APIキーの発行 ¶

「マスタ管理画面＞その他設定」にAPIキー管理画面へのボタンが表示されます。 APIキー管理画面を開き、APIキーの作成を行ってください。

APIキー名

APIキーを識別するためのラベルです。最大20文字で他のAPIキーと重複しない名前を指定してください。

操作許可リスト

アクセス出来る情報と操作権限をAPIキー毎に設定します。許可されない情報へのアクセス、操作は出来ません。 各エンドポイント毎に必要となる権限が設定されていますので、リファレンスで確認してください。

IPアドレス制限

APIのエンドポイントへアクセス出来るIPアドレスをAPIキー毎に設定出来ます。設定をしない場合、全てのIPアドレスからアクセス可能です。 IPアドレスははCIDR表記を使用して指定します。単一のIPを指定する場合でも「/32」まで入力してください。

認可 ¶

アクセストークンについて ¶

各エンドポイントへのリクエストには、アクセストークン（APIキー≠アクセストークン）が必要となります。 /v1/ext/まはた/v1/ext2/から始まるエンドポイントへのリクエストには以下のヘッダを設定してください。

Authorization: Bearer <アクセストークン>

アクセストークンは、トークンエンドポイントを使用し、取得することが出来ます。

共通 ¶

レスポンス形式 ¶

各エンドポイントのレスポンスは共通のプロパティを持っています。

  • code サーバの処理結果コードです。成功した場合、200が返ります。

  • message サーバの処理でなにか問題が発生した場合など、その詳細が含まれます。

  • timestamp レスポンスを返した時間。

  • requestId リクエスト毎に割り振られる一意な値。

  • result サーバでの処理結果。エンドポイントごとにプロパティが異なります。

以降、レスポンスの説明では、result以外のプロパティについては省略いたします。

{
    "code": "200",
    "message": [
        {
          "message": "Success"
        }
    ],
    "timestamp": "2020-04-02T12:00+09:00",
    "requestId": "xxxxx-xxxxx-xxxxx-xxxxx",
    "result": {
    }
}

エラーコード ¶

  • 400 BAD_REQUEST
    URLパラメータまたは、リクエストボディに含まれる値に問題があります。
    設定値を再度確認してください。

  • 401 UNAUTHORIZED
    アクセストークンが無効です。アクセストークンの有効期限が切れていないか、正しくアクセストークンが設定されているか見直してください。

  • 403 FORBIDDEN
    権限が不足しています。APIキーに設定されている、権限を見直してください。

  • 404 NOT_FOUND
    存在しないエンドポイントです。URLを見直してください。

  • 500 INTERNAL_SERVER_ERROR
    システムに問題が発生しています。時間を置いて再度リクエストしてください。解消しない場合には、サポートまでお問い合わせください。

  • 504 GATEWAY_TIMEOUT
    所定の時間以内に処理が完了しませんでした。リクエスト内容を見直すか、時間を置いて再度リクエストしてください。解消しない場合には、サポートまでお問い合わせください。

リソース定義 ¶

リソース定義について ¶

CAREER PLUSでは、APIを通じてアクセスできる情報を「リソース」と呼びます。
APIを通じてアクセス出来るリソースの種別は以下の通りです。

  • career 求職者

  • career_workexperience 求職者職歴

  • career_action 求職者対応履歴

  • client 企業

  • client_action 企業対応履歴

  • department 部署

  • order 求人

  • wrkcareer 求職者候補

  • progress 進捗

  • progress_history 進捗履歴

  • file ファイル

各リソースには、複数の項目を持っています。 例えば、「求職者」リソースには、「姓」や「名」、「性別」などの項目が存在します。
それぞれのリソースにどのような項目が存在するかは、リソース定義エンドポイントで確認出来ます。

- 関連リソース ¶

CAREER PLUSのリソースには、それぞれ関連性があるものが存在します。（例：企業と求人）
「検索」のエンドポイントでは、関連するリソースを使用した検索が可能です。
また、「取得」のエンドポイントでは、関連するリソースの項目も合わせて取得が可能です。
どのリソースが関連リソースにあたるかは、各エンドポイントのリファレンスに記載しております。

リソース定義  ¶

リソース毎の定義情報を取得出来ます。 取得出来る情報は以下の通りです。

  • resourceCategory リソース種別

  • items 項目リスト: 指定した種別のリソースに含まれる項目の一覧です。

    • itemId 項目ID: 項目を一意に識別する値です。
    • label 項目ラベル: 項目の日本語名です。
    • itemType 項目タイプ: 項目のタイプです。タイプにより、バリデーションの方法等が異なります。
    • isReadOnly 読み取り専用: trueの項目は、「追加」「更新」操作時に対象に含めることが出来ません。
    • isNotUpdatable 更新不可: trueの項目は、「更新」操作時に対象に含めることが出来ません。
    • isSortable ソート可否: 検索時のソートキーとして使用出来る項目はtrueとなります。
    • validationRule 検証ルール
      • required 必須: trueの項目は「追加」操作の場合、必ず対象に含める必要があります。「更新」操作の場合には、空の値で更新出来ません。
      • regexString 文字列チェックルール: 値に設定出来る文字列のチェックルールです。正規表現で表されます。配列になっており、複数ある場合、全ての正規表現にマッチする必要があります。
      • minLength 最短文字列長: 文字列の最短文字数です。
      • maxLength 最長文字列長: 文字列の最長文字数です。
      • minValue 最小値: 最小値です。項目に入力できる値が数値のみの場合に設定されます。
      • maxValue 最大値: 最大値です。項目に入力できる値が数値のみの場合に設定されます。
      • onlyEmail Emailアドレスチェック（RFC準拠）: 入力出来る値がメールアドレスを想定している項目の場合、trueが設定されます。
      • codeName マスターコード名: マスターを参照している項目に設定されます。参照しているマスタに存在する値のみ入力出来ます。

項目タイプには以下のものが存在します。

  • text: 文字列として扱います。

  • number: 数値として扱います。

  • textarea: 文字列として扱います。改行(\n)が含まれます。

  • selectone: 参照しているマスタに存在する値を1つ保持します。

  • search: 参照しているマスタに存在する値を1つ保持します。(selectonetと同じですが、マスタの値が多い場合searchになることがあります。)

  • select: 参照しているマスタに存在する値を複数保持します。

  • date: 年月日の情報を保持します

  • datetime: 年月日、時分秒の情報を保持します。（CAREER PLUSの画面上は秒の情報が表示されない項目があります。）

リソースについて ¶

各リソース毎に、検索、取得、登録、更新、削除のエンドポイントが存在します。 ここでは、各エンドポイントへのリクエスト内容およびレスポンス内容について説明します。

検索 ¶

検索エンドポイントでは、JSON形式のクエリを組み立てることで、柔軟に検索条件を指定出来ます。 （検索に時間が掛かりすぎる場合、タイムアウトすることがあります。）

リクエスト

  • limit 1回のリクエストで取得する検索結果の上限件数。未指定の場合20件。(最大100)

  • offset 検索結果全体のうち、取得する結果の開始位置。未指定の場合0。

  • sort 検索結果をソートして取得した場合に指定。未指定の場合、並び順は保証されません。
    (ソートキーに指定する項目の内部仕様により、文字列的にソートされる項目と、数値的にソートされる項目があります。)

    • itemId ソートキーとなる項目ID。
    • order 並び順の指定。asc(昇順)またはdesc(降順)を指定します。未指定の場合、asc(昇順)となります。

  • condition 検索条件。詳細な指定方法はこの後の章で記載します。未指定の場合、リソースの全件が選択されます。

    • compoundType items配列の要素をandAND条件とするかorOR条件とするかを指定します。
    • items 条件配列
      • itemId 検索条件とする項目ID。
      • searchType 値との比較方法。
      • value 比較する値。
{
  "limit": 20,
  "offset": 20,
  "sort": [
    {
      "itemId": "CAREER#LASTNAME",
      "order": "desc"
    }
  ],
  "condition": {
    "compoundType": "and",
    "items": [
      {
        "itemId": "CAREER#MEMO",
        "searchType": "LIKE",
        "value": "メモ"
      }
    ]
  }
}

レスポンス

検索エンドポイントのレスポンスは以下のような形式となります。

  • result 処理結果
    • limit リクエストで指定したlimitの値。
    • offset リクエストで指定したoffsetの値。
    • count 検索にヒットした全件数。
    • ids 検索にヒットしたリソースのIDの配列。最大でlimitの件数まで取得される。
{
  "code": "200",
  "message": [
    {
      "message": "Success",

- 比較方法 ¶

比較方法としてsearchTypeに指定出来る値には次の物があります。

  • GT 大なり（＞）

  • LT 小なり（＜）

  • GE 以上（≧）

  • LE 以下（≦）

  • EQ 等しい

  • NOT_EQ 等しくない

  • LIKE 含む（部分一致）

  • NOT_LIKE 含まない

  • START_WITH 先頭一致

  • END_WITH 後方一致

  • ENTERED 入力済み（※valueには空文字（’’）を指定してください）

  • NOT_ENTERED 未入力（※valueには空文字（’’）を指定してください）

項目タイプにより使用出来る比較方法が異なります。

    "items": [
      {
        "itemId": "CAREER#LASTNAME",
        "searchType": "EQ",
        "value": "山田"
      },
      {
        "itemId": "CAREER#FIRSTNAME",
        "searchType": "EQ",
        "value": "太郎"
      }
    ]
  }
}

リクエスト

取得エンドポイントのレスポンスは以下のような形式となります。

  • result
    • id 取得したリソースID
    • resourceCategory リソース種別
    • items 項目の配列
      • itemId 項目ID
      • value 値
{
  "code": "200",
  "message": [
    {
      "message": "Success",

    }
  ],

    "id": "123",

    "items": [
      {
        "itemId": "CAREER#CAREER_ID",
        "value": "123"
      },
      {
        "itemId": "CAREER#LASTNAME",
        "value": "山田"
      },
      {
        "itemId": "CAREER#FIRSTNAME",
        "value": "太郎"
      }
    ]
  }
}

値の形式は項目のタイプによって異なります。

  • textタイプ: そのまま表示されます。
{
  "itemId": "CAREER#CAREER_ID",
  "value": "山田"
}
  • textareaタイプ: 改行は\nとして表示されます。
{
  "itemId": "CAREER#MEMO",
  "value": "1行目\n2行目"
}
  • selectoneタイプ: そのまま表示されます。
{
  "itemId": "CAREER#SEX",
  "value": "1"
}
  • searchタイプ: そのまま表示されます。
{
  "itemId": "CAREER#ZIP",
  "value": "1001234"
}
  • selectタイプ: 配列形式として表示されます。
{
  "itemId": "CAREER#PREF",
  "value": ["8","9","10"]
}
  • dateタイプ: 「yyyy/MM/dd」の形式で表示されます。(例：「2021/01/02」2021年1月2日)
{
  "itemId": "CAREER#BIRTH_DATE",
  "value": "2021/01/02"
}
  • datetimeタイプ: 「yyyy/MM/dd HH:mm」の形式で表示されます。(例：「2021/01/02 23:59」2021年1月2日 午後11時59分)
{
  "itemId": "CAREER#UPDATE_DATE",
  "value": "2021/01/02 23:59"
}
