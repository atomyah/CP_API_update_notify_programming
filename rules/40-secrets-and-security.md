# ルール: 秘密情報と安全性

## APIキー

- **リポジトリに置かない。**環境変数か、リポジトリ外の設定ファイルから読む。
- ログ・エラーメッセージ・Slack 通知本文に出さない。
  例外のスタックトレースにリクエストボディが載る実装にしない。
- 仕様書に「ブラウザから直接 API を実行しないようお願い致します」と明記されている。
  APIキーがブラウザに渡る構成（フロントから直接叩く、キーを含む URL を発行する等）を作らない。
- CP の APIキー管理画面では IP アドレス制限（CIDR）を設定できる。
  常時起動サーバの固定 IP を `/32` で登録する。

## 権限は読み取りのみ

このアプリは CP に書き戻さない。APIキーには**作成・更新・削除を一切付与しない**。

付与すべき権限は `docs/design/05-apikey-request.md` に列挙してある。
実装の都合で書き込みが必要になったと感じたら、それは設計の誤りなので、
権限を足す前に設計を見直す。

## 個人情報

CP が扱うのは求職者の氏名・連絡先・年収などの個人情報。

- 通知本文に載せる項目は YAML で明示的に列挙したものだけにする。
  「取得したものを全部出す」実装にしない。
- ログにレスポンスボディをそのまま吐かない。
  デバッグ時も項目 ID とリソース ID のみ、値はマスクする。
- SQLite の `snapshots` には**値そのものではなくハッシュ**を保存することを既定とする。
  差分検知にはハッシュで足りる。値が必要なのは通知本文の組み立て時だけで、
  そのときは API から取り直すか、`notified` に組み立て済み本文を短期保持する。
  例外は「遷移前後の値を通知したい」項目（要件1）。この場合のみ値を保存し、
  対象項目を YAML で明示させる。
- SQLite ファイルと設定ファイルはリポジトリ外の、パーミッションを絞ったディレクトリに置く。

## 通知先

- Slack の Webhook URL / Bot トークンも秘密情報として同様に扱う。
- 要件4のメール宛先は `CAREER#CHARGE_EMAIL`（CP 上の担当者メールアドレス）。
  **値が空・不正なときに送信をスキップして黙らない。**
  フォールバック宛先（管理者）へ「宛先不明で通知できなかった」旨を送る。
- 誤送信の影響が大きいので、本番相当のデータで動かす前に
  「全通知をフォールバック宛先にリダイレクトするドライラン設定」を用意する。
